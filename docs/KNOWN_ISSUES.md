# 已知问题

## 一、需要用户手动处理的问题

### 1. PyQt6-WebEngine 安装
**问题**: PyQt6-WebEngine 在某些 Windows 环境安装可能失败（需要 MSVC 编译器）
**解决**: 
- 使用 `pip install PyQt6-WebEngine` 预编译 wheel
- 如果失败，程序会自动降级到原生 Qt UI

### 2. Ollama 模型下载
**问题**: richardyoung/qwen3.6-27b-abliterated:latest 模型约 15GB，首次下载时间长
**解决**: 
- 安装脚本会提示用户运行 `ollama pull`
- 模型未下载时 LLM 会返回降级错误信息

### 3. UI RC1 路径
**问题**: 程序查找 UI RC1 的 index.html 时可能路径不匹配
**解决**: 
- 优先使用 `ui_runtime/xixi_ui_rc1_integrated/index.html`；原始 UI 文档包保留在 supplements
- 程序会尝试多个候选路径

## 三、潜在问题

### 1. 跨线程数据库访问
**问题**: SQLite 在多线程环境下可能遇到锁竞争
**缓解**: 每个线程使用独立连接，使用 WAL 模式
**长期解决**: 考虑迁移到 PostgreSQL 或 SQLite 连接池

### 2. 大模型上下文溢出
**问题**: 65536 上下文在极长对话后仍可能溢出
**缓解**: 对话历史限制 20 轮，记忆摘要压缩
**长期解决**: 实现智能上下文压缩/摘要

### 3. Soul Schema 校验严格性
**问题**: 模型可能不总是输出完美符合 schema 的 JSON
**缓解**: 一次修复重试机制
**长期解决**: 更灵活的 schema 或后处理管道

### 4. 工具执行安全性
**状态**: `code.execute` 当前保持关闭，不使用 `eval` 冒充沙箱。
**后续**: 只有在独立 tool-worker、资源限制和审计链完成后才能启用。

### 5. Windows 停止流程
**状态**: `stop.bat` 已改为读取 `data/xixi.pid`，只关闭西西对应进程。
**限制**: 仍需在目标 Windows 电脑验证正常退出与强制退出两条路径。

## 四、测试覆盖缺口

以下功能有实现但缺乏自动化测试：
- WebSocket 序列号乱序拒绝
- Body 无资产回退
- 任务重启恢复
- 生命周期备份/回滚
- 权限范围授权缓存

## 五、性能考虑

- 大模型（27B）在普通消费级 GPU 上生成速度约 10-20 tokens/秒
- 流式输出对 UI 更新频率有一定压力
- 建议：GPU 显存 >= 16GB，内存 >= 32GB
